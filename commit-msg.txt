fix: description unique stable + source Met.no en fallback

Deux changements lies a la confiance dans les donnees affichees :

1. Plus de double description au demarrage :
   Avant, le code affichait generateDescription(w) (template
   statique) puis lance generateAIDescription(city, w) en
   arriere-plan qui remplace par le LLM Pollinations. Resultat
   visuel : "paf une autre" description qui apparait 1-3s apres
   l'autre et derange l'utilisateur.
   Fix : on n'utilise plus que generateDescription(w) (template
   deterministe, sans appel reseau). Pas de LLM, pas de saut,
   pas de temps d'attente. Une seule description, stable,
   generee localement a partir des vraies observations.

2. Source Met.no ajoutee en fallback :
   - Open-Meteo etait l'unique source reelle.
   - Ajout Met.no (Institut Meteorologique Norvegien), gratuit,
     sans cle, modele numerique de haute qualite (Arome-MetCoCo
     + ECMWF), jusqu'a 10 jours de prevision.
   - Nouveau fetchWeatherReliable(lat, lon) essaie dans l'ordre :
     Open-Meteo -> Met.no -> procedural interne.
   - Si une source tombe (rate-limit, reseau, panne), l'autre
     prend le relais immediatement (grace au try/catch en
     cascade) : redondance sans interruption pour l'utilisateur.
   - Met.no exige un User-Agent (sinon HTTP 403), on en envoie
     un descriptif ("MeteoApp/1.0 tomtechclair.github.io").
   - Cache memoire 10 min pour respecter la rate-limit Met.no
     (1 req / 10s / IP).
   - Mapping complet des codes Met.no -> codes WMO (clearsky,
     fair, partlycloudy, etc.) pour rester compatible avec
     le reste de l'app.
