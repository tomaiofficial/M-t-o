feat: panneau parametres mobile + detection pluie/orage instantanee

Le user demande :
1. Le panneau parametres prend tout l'ecran sur mobile
2. Pluie et orages pas assez rapides a detecter

PARTIE 1 - PANNEAU MOBILE

Avant :
- panel-content max-width 480px, padding 28px 24px 40px
- Pas de max-height : risque de depasser la fenetre mobile
- Liste lineaire sans hierarchie
- Pas de safe-area-inset (cache la barre d'URL iOS)

Apres :
- max-height 88vh + overflow-y auto (scroll interne)
- Padding adapte avec env(safe-area-inset-bottom)
- Poignee draggable en haut (style iOS, ::before 36x4)
- Groupes "Affichage" / "Actualisation" / "Position"
  avec h3 de section (titres compacts)
- Cards arrondies par setting (12px) au lieu de
  simples lignes separees par border
- Scrollbar fine (4px) pour rester discret
- Bouton "Fermer" plus large et mieux style
- Responsive : sur >600px (desktop) max-width 480px
  avec marges, sur mobile full-width avec coins arrondis

PARTIE 2 - PLUIE/ORAGE INSTANTANE

Avant : tickLive toutes les 60s, Open-Meteo met a
jour ses donnees toutes les 5-15min.

Apres : fastTick toutes les 20s !

Nouveau fastTick() :
- Appelle Open-Meteo avec UNIQUEMENT les parametres
  "current" (tres leger : ~1KB de reponse)
- Verifie pluie (precipitation > 0.05mm/h)
- Verifie orage (weather_code 95/96/99)
- Si pluie demarree/arretee OU orage detecte :
  -> force applyLiveTick immediat
  -> met a jour banniere pluie + orage
  -> flash visuel pour confirmer la mise a jour
- Anti-stacking (fastPollInFlight flag)
- Premier check 5s apres lancement

Demarrage : startFastPoll() appele dans init() en
plus de tickLive.

Limitations :
- Open-Meteo met a jour ses observations toutes
  les 5-15min selon les stations
- Donc le poll detecte ce que leur serveur voit
  deja -> si pas encore actualise cote Open-Meteo,
  on a juste les memes donnees
- Pour vraiment instantane il faudrait du radar
  (RainViewer API) - pas implemente ici
