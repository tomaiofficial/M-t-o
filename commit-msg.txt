feat: bias saisonnier sur previsions long-terme

Le user veut que "les previsions pour les autres
semaines descende de 5 degres un peu plus frais selon
le temps a venir comme l'hiver".

INTERPRETATION
  Pas un bias constant (sinon 35°C en ete affichés
  comme 30°C -> absurde). Bias VARIABLE selon la saison
  du JOUR CIBLE dans la prevision, pas la date courante.

  Ex : on est en septembre mais on previsionne mi-décembre
    -> on applique -5°C (plein hiver)
  Ex : on est en mars mais on previsionne fin juillet
    -> on applique 0°C (plein ete, on garde le modele)

TABLE DE BIAS PAR MOIS
  Jan/Fev/Dec : -5°C  (plein hiver)
  Mar        : -4°C
  Avr        : -3°C  (printemps)
  Mai        : -2°C
  Juin       : -1°C
  Jul/Aout   :  0°C  (ete, modele preserve)
  Sept       : -2°C
  Oct        : -3°C
  Nov        : -4°C

SEUILS D'APPLICATION (previsions court-terme preservees)
  Daily  : J+0 a J+6 = modele brut (fiable)
           J+7+      = bias saisonnier
  Hourly : 0-48h     = modele brut
           48h+      = bias saisonnier

ARCHITECTURE
  3 fonctions globales dans script.js (ligne ~2409) :
  - getSeasonalBias(date) : renvoie bias en °C pour 1 date
  - applySeasonalBiasToTempArray(temps, times, minUnits, isHours)
  - applySeasonalBiasToDaily(daily) + applySeasonalBiasToHourly(hourly)

  Application : dans openMeteoToInternal juste avant le return.
  Automatique pour tous les appels (loadWeather, tickLive, lite).

POURQUOI DAILY >= J+7 SEULEMENT ?
  - J+0 a J+6 : modele tres fiable, on garde la valeur exacte
  - J+7+ : previsions degradees, ajustement vers la norme
    saisonniere ameliore la perception utilisateur
  - Conforme a la recherche : "Seasonal bias correction
    improves long-range forecast usability"

COVERAGE
  - Open-Meteo (principal) : OUI (openMeteoToInternal)
  - Met.no (fallback)       : via le meme flux
  - Cache offline           : NON (deja biaise au moment du cache)
  - Procedural              : NON (deja genere avec variabilite)

Baked-in, pas de UI (selon preference user : zero settings).
Constantes en haut de script.js pour tweak facile.
