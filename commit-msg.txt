fix: API meteo retournee OK (fire_weather_index invalide)

Le user : "corrige les donnnes meteo ils disent n'importe
quoi"

CAUSE
Le commit feat:flamme ajoutait fire_weather_index
dans les parametres hourly de l'appel Open-Meteo.
MAIS fire_weather_index N'EXISTE PAS dans l'endpoint
/v1/forecast d'Open-Meteo ! C'est une variable
disponible UNIQUEMENT sur un endpoint dedie
(open-meteo.com/en/docs/fire-weather-api).

Resultat : Open-Meteo renvoyait une ERREUR 400
"Data corrupted at path ''. Cannot initialize
SurfacePressureAndHeightVariable from invalid
String value fire_weather_index" et l'app
n'avait AUCUNE meteo -> affichage de dernier
cache ou valeurs par defaut.

Reproduction :
curl "https://api.open-meteo.com/v1/forecast?latitude=...
&hourly=fire_weather_index"
-> 400 "invalid String value fire_weather_index"

FIX
1. Suppression du param fire_weather_index
2. Calcul local du risque d'incendie
   (computeFireRisk) base sur temp/humidity/wind/precip
   qui sont deja retournes par l'API standard.
   Echelle approx 0-30 :
   - 0-3   : Faible (cache)
   - 3-8   : Modere (jaune)
   - 8-15  : Eleve (orange)
   - >15   : Extreme (rouge)
3. Seuils d'affichage ajoutes en consequence
   (anciens seuils 5/15/30 ramenes a 3/8/15)
4. Tooltip passe de "FWI" a "indice" (plus
   precis vu que ce n'est plus le FWI canadien)

RESULTAT
- API Open-Meteo retourne les donnees correctement
- Paris : 15h avec 31.5C/29%/4.3km/h -> score ~17.5
  (extreme,'affiche le feu)
- Risque incendie reste informatif sans casser
  toute la meteo

VERIFICATION
curl "https://api.open-meteo.com/v1/forecast?latitude=48.85&longitude=2.35&hourly=temperature_2m,relative_humidity_2m,wind_speed_10m,precipitation"
-> 200 OK avec donnees
