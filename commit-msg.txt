fix: flash "Orages" au lancement corrige

Le user signalait : "au lancement la meteo met tout
le temps orage et puis 5 sec apres elle se met a jour".

Cause : race condition entre LITE fetch (~1s) et FULL
fetch (~5s) + code WMO non verifie par observation.

Flux avant correction :
1. Skeleton affiche (~1s)
2. LITE fetch termine, renderCity appelle wmoInfo(95)
   qui retourne "Orages" car le modele prevoyait un orage
3. Skeleton retire, user voit "Orages"
4. ~5s plus tard, FULL fetch termine avec meteo reelle,
   renderCity remplace avec la bonne condition
5. User voit donc "Orages" pdt 5s, puis la vraie condition

Fix : classifyLiveCondition modifie pour traiter le cas
95/96/99 (code orage) SANS precipitation observee :

AVANT : si code 95-99 -> toujours "Orages" ou "Orages violents"
MAINTENANT :
- Code 95-99 ET pluie observee (>0.05 mm/h)
  -> "Orages" / "Orages violents" (vrai orage en cours)
- Code 95-99 SANS pluie + couverture nuageuse >= 70%
  -> "Couvert" (le modele a vu un orage mais il n'a pas
     encore demarre, on montre le label realiste)
- Code 95-99 SANS pluie + couverture nuageuse < 70%
  -> "Risque d'orages" (info moins alarmiste)

renderCity utilise aussi classifyLiveCondition (et non
plus juste wmoInfo) pour eviter le flash initial :
- finalCode = code override par liveInfo ou code WMO
- Theme, particules, label utilisent finalCode
- Pas de 1er render incoherent avec ce qu'applyLiveTick
  affichera juste apres

Resultat : plus de "Orages" qui flash 5s au lancement.
Le label montre directement la condition la plus realiste
selon l'observation.
